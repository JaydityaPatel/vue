# Phase 10: Reports, history, and recurring weaknesses

- `GET /interviews/{id}/report` returns the stored report, four average rubric dimensions, coding breakdown when present, and scored turn evidence. `POST` remains supported for clients that use the previous report action. Report feedback is generated with the `final_evaluation` LLM task from the actual question, answer, topic, rubric scores, feedback, expected/missing concepts, skill tags, and coding evidence. Suggestions are instructed to cite a topic and turn ID.
- Interview completion generates and stores the report in the completion transaction for both HTTP answer and voice completion paths. Empty sessions remain abandoned and do not produce reports.
- `GET /interviews?page=1&page_size=20` returns the authenticated user's paginated sessions with date, status, mode, and report score.
- `GET /users/me/weaknesses` summarizes tagged scores over completed sessions. A tag must occur in at least two distinct sessions and have technical correctness or completeness below `WEAKNESS_SCORE_THRESHOLD` (2.5). SQLite expands the persisted JSON tag array and groups by controlled taxonomy tag and session in SQL; the fallback dialect path keeps the same controlled-tag filter. Trend compares early and late per-session means, so repeated follow-ups in one session do not dominate it. Changes within 0.25 points are reported as flat.
- The History page displays sessions, reports, and weakness trends, including empty states.
- Phase 10 skill-tag reuse: Random and resume/JD planning now asks for a separate `skill_tag` chosen exactly from the full supplied taxonomy, while retaining descriptive topic names. Job web enrichment receives the same taxonomy list and mapping rule. Reuse remains deterministic exact matching against the selected canonical label; unknown non-null selections are rejected. Fuzzy matching was not added because it can merge genuinely distinct skills.
- Duplicate-tag repair: run `python main/scripts/merge_duplicate_skill_tags.py` from the repository root for a dry run or add `--apply` to merge the two known alias pairs. The script anchors itself to `main/backend` for database settings. Apply mode creates a SQLite backup in the system temp directory, rewrites JSON `TurnScore.skill_tags` and session `skill_tag_id`/`skill_tag` references in one transaction, then deletes the duplicate taxonomy rows. The Phase 10 repair reduced the table from 21 to 19 rows. Before/after weakness output is saved in `reports/phase10-skill-tag-merge.json`.

The existing configured database already has usable repeated history. A read-only call to `get_recurring_weaknesses` for a Phase 1-8 verification account with three completed sessions returned four recurring tags. Exact results are saved in `reports/phase10-weakness-readout.json`; no additional test history was added.
